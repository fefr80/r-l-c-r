## 开服前先确认四件事

这四项任何一项不对，后面都会卡住，而且报错信息通常不指向真正的原因。

**版本链。** 原版只要版本号对上就行，整合包要对齐一串：游戏主版本、模组加载器及版本、MOD 列表与每个 MOD 的版本、config 目录与脚本改动。差一个就报 Mod Rejection，后面跟着一长串不匹配的模组名。RLCraft 的主版本固定是 1.12.2，加载器固定是 Forge，所以真正容易出错的是"谁的客户端多装了一个模组"或"服务端包和客户端包不是同一次下载的"。整包分发，别让每个人自己手装。

**Java 版本。** MC 1.12.2 及更老的版本用 Java 8，1.16.5 左右用 Java 11 兼容性更好，1.18 以上用 Java 17。RLCraft 属于第一类，服务端就装 Java 8。CentOS 系的机器上一条命令：


yum install java-1.8.0-openjdk.x86_64


用启动器自带的 Java 运行时经常出问题，建议单独装一个 JDK 再在启动器里手动指向它。

**内存。** 这里有两套口径，对象不同，不要混着用。

RLCraft 官方 wiki 的手动安装页写的是客户端分配 4 GB，JVM 参数从 `-Xmx2G` 改成 `-Xmx4G`，并且明确说超过 4G 反而可能因为 Java 自身的工作方式导致内存泄漏。这是针对客户端 + 整合包本体说的。

服务端是另一回事。泛整合包的经验值是服务端 4～8G 内存起步；另一个常被引用的规则是分配量不超过物理内存的 50%，16G 的机器最多给 8G，大型整合包建议 `-Xmx6G -Xms6G -XX:+UseG1GC -XX:MaxGCPauseMillis=200`。两条规则一条针对 RLCraft 单个包，一条针对"几百个模组的大型整合包"这个泛化场景，落到你的机器上还是要实测。

判断方法很直接：进游戏按 F3，看右上角 Allocated Memory 和 Used Memory。长期高于 80% 说明给少了，长期低于 30% 说明给多了。

**磁盘。** 中等体量的整合包建议 SSD 上预留 20G 以上：游戏目录本体约 5～8G，核心模组和运行时约 1G，存档跑图半径一大容易超过 5G，再装高清材质单包就可能 10～20G。这组数字是典型场景的建模值，不是实测承诺，但用来估算够不够很实用。

## 从零到朋友能进：完整操作顺序

**第一步，拿服务端包。** 去 CurseForge 的 RLCraft 页面下载 Server Pack。同一页面也能下客户端整合包，两边必须是同一次下载的对应版本。

**第二步，装 Forge。** 下载 `forge-1.12.2-14.23.5.2860-universal.jar`。客户端安装时选 install client；服务端这边是把 Forge 的 jar 和 Server Pack 解压后的文件放在同一个目录里。

这里要提醒一句：网上很多 2020 年前后的中文教程写的是 `forge-1.12.2-14.23.5.2854`，那个版本号已经旧了。RLCraft 官方 wiki 的安装页现在给的是 `14.23.5.2860`，客户端启动器里的版本也要选 `1.12.2-forge1.12.2-14.23.5.2860`。按老教程装 2854 不一定会崩，但遇到莫名其妙的 library 报错时，先换成 2860 重来一遍是最省时间的做法。

**第三步，同意 EULA。** 第一次启动一定会失败，屏幕上出现 `stopping server` 之类的提示，原因就是没同意 Mojang 的条款。打开目录里的 `eula.txt`：


vim eula.txt


把里面的 `eula=false` 改成 `eula=true`，保存退出（按 `i` 进入编辑，改完按 `Esc`，输入 `:wq` 回车）。再启动就正常了。

**第四步，启动。** 命令形如：


java -Xmx4G -Xms4G -jar forge-1.12.2-14.23.5.2860.jar


内存数字按你机器的实际情况调。看到控制台刷出一串 `help` 之类的提示，说明服务端起来了。

**第五步，给自己管理员权限。** 在控制台输入：


op 你的用户名


**第六步，让它在后台常驻。** 先装 screen：


yum install screen


新建一个会话：


screen -S mc


在里面启动服务端，然后按 `Alt + A` 再按 `D` 脱离。之后想回到这个会话用 `screen -r mc`。`-S` 是创建，`-r` 是返回。不脱离就直接关终端，服务端会跟着一起死。

**第七步，把地址发给朋友。** 格式是 `公网IP:25565`。连不上先查两件事：云服务器安全组有没有放行 25565 端口，以及朋友用的客户端整合包版本是不是和你完全一致。

## 几个高频报错怎么查

**Mod Rejection，后面跟一长串模组名。** 版本链没对齐。先比对客户端和服务端的 MOD 列表，再比对每个 MOD 的版本号。最常见的情况是某个人从别处单独下了一个"优化版"客户端，多装或者少装了几个模组。

**启动时出现 stopping server。** `eula.txt` 里还是 `false`。改完保存，重新启动。

**无法建立 library。** 这是早期 Forge 版本在部分环境下的坑，2020 年前后的中文教程专门有一节讲怎么另外找 library 包解压合并。那些修法来自个人博客，配套的网盘地址大多已经失效，不建议照着做。现在的处理方式简单得多：删掉目录重来一遍，用官方 wiki 给的 `14.23.5.2860` 走标准流程，多数情况下不会再出现。

**朋友连不上，但服务端日志正常。** 按这个顺序查：安全组/防火墙有没有放行 25565；地址是不是写成了内网 IP；客户端整合包版本是否和服务端完全一致；服务端是不是在 screen 里跑着而不是跟着你的 SSH 会话一起退出了。
